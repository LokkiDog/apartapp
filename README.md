# Aparts CRM

Mobile-first CRM для управления апартаментами в Банско. Интерфейс на русском, денежные суммы вводятся и хранятся в EUR с точностью до двух знаков, а операционное планирование ведётся по датам без времени.

## Запуск

1. Скопируйте `.env.example` в `.env` и задайте `DATABASE_URL` (по умолчанию локальный порт `55432`), `NUXT_SESSION_PASSWORD`, `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`.
2. Запустите инфраструктуру: `docker compose up -d`.
3. Выполните `npm install`, `npm run db:migrate`, затем `npm run dev`.

Первый администратор создается идемпотентно при старте сервера из переменных окружения.

## Production

Production работает в Docker Compose за host Nginx на отдельном VPS по адресу
`https://crm.aparts-bansko.com`. Образ приложения собирается на Node 22,
PostgreSQL и фотографии хранятся в отдельных Docker volumes, а миграции
выполняются одноразовым контейнером перед запуском новой версии.

Подготовка VPS, DNS, TLS, `.env.production`, внешний SMTP и автоматический
деплой через GitHub Actions описаны в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
Автоматические резервные копии в текущую схему не входят.

## Настройки уведомлений

В профиле пользователь выбирает доставку каждого события в CRM, Push и Email.
По умолчанию CRM и Push включены, Email выключен. Изменения относятся к новым
уведомлениям; история ленты сохраняется. Push дополнительно требует разрешения
браузера и подключения текущего устройства.

Перед запуском этой версии примените миграцию `0049_notification_preferences`
через `npm run db:migrate`. Настройте существующий почтовый транспорт SMTP или
Brevo для доставки Email. Письма обрабатываются сервером каждые 30 секунд,
повторяются при ошибке до пяти попыток; очередь хранится в PostgreSQL.
`notification_email_queue.status = 'failed'` означает исчерпание попыток.
После отключения Email ожидающие отправки письма пропускаются. Запросы смены
пароля, приглашения и служебные события сессии этими настройками не отключаются.

## История обновлений

Страница «Что нового» использует `shared/config/changelog.ts`.
Записи перечисляются от новой к старой, тексты находятся в разделе `changelog`
переводов RU/EN/HE. Версии обозначаются датой `ГГГГ.ММ.ДД`; это номера записей
журнала, а не Git-теги. До публикации используйте статус `upcoming`, после
успешного деплоя меняйте его на `released` и указывайте фактическую дату выпуска.

Для анонса заполните `announcement` (обложка и краткие пункты) и включите
`enabled`. Автоматический попап использует только последнюю опубликованную
версию с анонсом. В черновике доступна кнопка «Посмотреть анонс» без отметки
просмотра. Закрытие опубликованного анонса или чтение журнала сохраняет просмотр
на аккаунте пользователя, независимо от устройства. Небольшие исправления можно
публиковать без анонса. Перед запуском примените `0050_release_announcements`.
При ошибке сохранения попап закрывается, а пользователь получает предупреждение;
в этом случае на другом устройстве анонс может появиться повторно.

## Проверки

`npm run typecheck` — TypeScript и Vue.

`npm test` — правила Zod-контрактов.

`npm run test:e2e` — Playwright-сценарии входа на mobile и desktop. Перед запуском поднимите PostgreSQL, примените миграции и запустите приложение; при другом адресе задайте `E2E_BASE_URL`.

`npm run build` — production build и PWA service worker.

`npm run lint:fsd` — Steiger для границ Feature-Sliced Design.

## Структура

- `app/pages` — тонкие Nuxt route entrypoints;
- `src` — FSD-слои (`app`, `pages`, `features`, `entities`, `shared`);
- `server/modules` — доменные use cases и правила доступа;
- `server/infrastructure` — PostgreSQL/Drizzle, audit, notifications, seed;
- `shared/contracts` — общие Zod-контракты.

Ролевые инструкции для ежедневной работы: [docs/OPERATIONS.md](docs/OPERATIONS.md).

Подключение независимых клиентов, настройка суперпользователя и порядок обновления:
[Клиенты и суперпользователь](docs/CLIENTS.md).
